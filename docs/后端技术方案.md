> **V3.0 → V3.1 变更**：P0（接口契约 + 端侧网络层）与 P1（后端骨架 + 算法平移）已完成，11 个接口实测通过。
>
> **V2.1 → V3.0 变更**：技术栈由「Spring Boot 3 + MyBatis-Plus + MySQL 8」改为「Node.js + TypeScript + Fastify + SQLite」。
> **变更理由**：核心算法已在端侧 `mock/XianWallMock.ets` 中用 ArkTS 实现（343 行），ArkTS 是 TypeScript 超集，

> 工期由 12 天降至 **4~5 天**，且演示只需一个 `node` 进程。
>
> 逐项实现状态见 [实现状态清单](./实现状态清单.md)；端侧改造点见 [项目设计文档 §12](./项目设计文档.md)。

## 1. 后端职责边界

| 职责 | 说明 |
| --- | --- |
| 路网数据服务 | 提供路口、进口道、路段信息 |
| 配时优化引擎 | Webster 模型计算周期与绿信比，输出四相位方案 |
| 交通流仿真 | 按时间生成各进口道流量、排队、延误 |

## 2. 数据源定位（先讲清楚，避免走弯路）

项目要求"将来数据由后端传输"，因此后端采用**混合三层数据源**，用适配器隔离：

```
┌─────────────────────────────────────────────┐
│  Service 层（只依赖 ITrafficSource 接口）      │
├─────────────────────────────────────────────┤
│ ① 仿真源 SimulationSource   ← 配时输入（必需） │
│ ② 路网源 OsmSource          ← 真实坐标拓扑    │
│ ③ 地图增强源 MapApiSource   ← 底图/态势（可选）│
└─────────────────────────────────────────────┘
```

### 2.1 各层能拿什么、不能拿什么（客观核查）

| 数据源 | 能提供 | 不能提供 | 在本项目的角色 |
| --- | --- | --- | --- |
| **仿真引擎**（自建） | 进口道分方向流量 `q`、饱和流率 `s`、排队、延误 | —— | **配时算法的唯一输入**（必需） |
| **OSM**（OpenStreetMap） | 真实路网拓扑、信号灯点位 `highway=traffic_signals`、WGS84 坐标；**免费、可离线、无需 Key** | 流量、配时 | 替换手工示意坐标，提升路网可信度 |
| **花瓣地图 Petal Maps** | Map Kit 底图 SDK、地理/逆地理编码、路径规划、POI 搜索 | **未见明确开放的实时路况接口**（需以实际开通能力为准）；不开放原始路网；国内数据精细度弱于高德/百度 | 端侧真实底图（可选增强） |
| **高德 / 百度** | 交通态势 API（路段拥堵等级、速度）、路网与 POI | **进口道流量与信号配时参数**；交通态势 API 通常需**企业开发者资质**，个人申请大概率不通过；坐标为 GCJ-02，接入需转 WGS84 | 路段态势展示（有资质才做） |

### 2.2 硬结论

> **地图 API 不能作为配时数据源。** Webster 模型需要的是「进口道分方向流量 q（辆/h）」与「饱和流率 s」，
> 任何地图开放平台都不提供这两项（也不提供信号配时参数）。地图 API 的正确用途是**路网与底图**，
> 配时输入必须由仿真产生，并在响应中标注 `dataSource` 字段如实说明。

### 2.3 三层落地方式

| 层 | 落地方式 | 阶段 | 工期 |
| --- | --- | --- | --- |
| ① 仿真源 | 从 `XianWallMock.ets` 平移为 `src/algo/*.ts` | P1 | 含在算法迁移内 |
| ② 路网源 | Overpass API 导出 OSM 数据 → 一次性生成 `src/data/network.ts` | P3 | 0.5~1 天 |
| ③ 地图增强源 | 定义 `MapApiSource` 接口，**默认空实现**，有资质再填 | P4 | 1 天（可选） |

## 5. 数据模型与存储

### 5.1 实体（与端侧 `entry/src/main/ets/model/` 同名同字段）

```ts
// src/types/Intersection.ts —— 与端侧保持一致，禁止另起命名
export type ApproachDir = 'EAST' | 'WEST' | 'SOUTH' | 'NORTH';
export type IntersectionType = 'CROSS' | 'T_SHAPE' | 'RING';

export interface Approach { dir: ApproachDir; lanes: number; saturationFlow: number; }
export interface Intersection {
  id: string;            // INT_01 ~ INT_15
  name: string;
  longitude: number;
  latitude: number;
  type: IntersectionType;
  approaches: Approach[];
}
export interface RoadSegment { id: string; name: string; fromId: string; toId: string; lanes: number; }
```

**命名约定（重要）**：端侧用 `intersectionId`、路段用 `fromId/toId`、时间为毫秒时间戳。
接口层一律输出**驼峰 + 毫秒时间戳**，数据库内部可用下划线列名，映射只在 `store/` 层做一次，避免两套命名污染上层。

## 7. 核心算法实现（★ 平移自端侧，口径必须一致）

> 以下 TS 代码与 `entry/src/main/ets/mock/XianWallMock.ets` 逐条对应。
> **任何一侧修改参数，另一侧必须同步**，否则会出现"前后端算出的周期不一样"这种最难排查的问题。

### 7.1 Webster 最优周期

```ts
// src/algo/webster.ts
const MIN_CYCLE = 60, MAX_CYCLE = 150;
const MIN_GREEN_THROUGH = 10, MIN_GREEN_LEFT = 8;

export interface PlanResult { cycle: number; greens: number[]; lostTime: number; }

/**
 * @param yEW 东西直行流量比  @param yNS 南北直行流量比
 * 左转相位按直行的 30% 折算（仿真未拆分转向流量）
 */
export function calculate(yEW: number, yNS: number, lostTime: number = 16): PlanResult {
  const yEWLeft = yEW * 0.3;
  const yNSLeft = yNS * 0.3;
  const Y = Math.min(0.92, yEW + yNS + yEWLeft + yNSLeft);   // 过饱和保护

  let cycle = Math.round((1.5 * lostTime + 5) / (1 - Y));
  cycle = Math.max(MIN_CYCLE, Math.min(MAX_CYCLE, cycle));   // clamp [60,150]

  const effective = cycle - lostTime;
  const alloc = (y: number, min: number): number =>
    Math.max(min, Math.round((effective * y) / Y));

  return {
    cycle,
    greens: [
      alloc(yEW, MIN_GREEN_THROUGH),      // 相位1 东西直行
      alloc(yEWLeft, MIN_GREEN_LEFT),     // 相位2 东西左转
      alloc(yNS, MIN_GREEN_THROUGH),      // 相位3 南北直行
      alloc(yNSLeft, MIN_GREEN_LEFT)      // 相位4 南北左转
    ],
    lostTime
  };
}
```

### 7.2 Webster 延误

```ts
// src/algo/delay.ts
export function websterDelay(cycle: number, greenRatio: number,
                             saturation: number, volumePerHour: number): number {
  const x = Math.min(0.95, saturation);            // 防止分母趋零
  const q = Math.max(0.05, volumePerHour / 3600);  // 辆/s
  const uniform = (cycle * Math.pow(1 - greenRatio, 2)) / (2 * (1 - greenRatio * x));
  const random  = Math.pow(x, 2) / (2 * q * (1 - x));
  return uniform + random;
}
```

### 7.3 流量仿真

```ts
// src/algo/simulator.ts
/** 确定性伪随机：与端侧 pseudo() 同算法，保证同一路口同方向结果稳定 */
export function pseudo(id: string, dir: string): number {
  const s = `${id}_${dir}`;
  let h = 7;
  for (let i = 0; i < s.length; i++) h = (h * 31 + s.charCodeAt(i)) % 9973;
  return h / 9973;
}

/** 高斯双峰：早 8 点、晚 18 点 */
export function peakFactor(hour: number): number {
  return 0.35 + Math.exp(-Math.pow(hour - 8, 2) / 4) + Math.exp(-Math.pow(hour - 18, 2) / 4);
}

export function simulateVolume(id: string, dir: string, hour: number): number {
  const base = 480 + pseudo(id, dir) * 420;        // 480 ~ 900 辆/h
  return Math.round(base * peakFactor(hour));
}
```

### 7.4 派生指标（与端侧 `TrafficUtil` / `getFlows()` 一致）

```
capacity(展示用) = 1650 × lanes × 0.48        // 绿信比固定，已知近似
saturation       = volume / capacity
queueLength      = round(saturation² × 14)
delay            = round(saturation × 45 + 6)
拥堵指数 index   = min(10, avg(全部进口道饱和度) × 10)
平均车速         = round(45 × (1 - avg / 1.6))
```

> ⚠️ **评价模块待修正**：端侧 `getEvaluation()` 中通行量（`before=0.93V, after=V`）与停车次数（`before=1.6x, after=1.2x`）
> 为**构造值**，优化前基线（`C=120, λ=0.42`）亦为硬编码。迁移到后端时**必须改为逐周期排队推演**，
> 否则只是把演示性数字搬到服务端。详见 [项目设计文档 §10.7](./项目设计文档.md)。

## 8. OSM 真实路网导出（P3）

### 8.1 为什么用 OSM

免费、可离线、**无需 Key**，能拿到 WGS84 真实坐标与信号灯点位，论文"路网建模"章节可直接写"基于 OpenStreetMap 开源路网数据"。
地图厂商 API（花瓣/高德/百度）均不开放原始路网数据下载。

### 8.2 导出步骤

1. 打开 <https://overpass-turbo.eu/>，把地图定位到西安城墙内。
2. 执行以下 Overpass QL（bbox 为城墙范围）：

```
[out:json][timeout:60];
(
  node["highway"="traffic_signals"](34.2478,108.9286,34.2768,108.9774);
  way["highway"~"^(primary|secondary|tertiary)$"](34.2478,108.9286,34.2768,108.9774);
);
out body geom;
```

3. 导出 GeoJSON，筛选落在城墙范围内的信号灯节点与主干道。
4. 与现有 `INT_01~INT_15` 按名称/位置做人工匹配，生成 `data/network.json`（保留原 id 不变，只替换坐标与路段几何）。
5. `intersection.source` 字段标记 `OSM`（匹配到）或 `MANUAL`（人工补录）。

### 8.3 已知风险

| 风险 | 对策 |
| --- | --- |
| OSM 国内信号灯点位**覆盖不完整**，20 个可能查不全 | 匹配到几个算几个，其余保留 `MANUAL` 并在论文中如实说明覆盖率 |
| 坐标与现手工值存在偏差 | 只替换明确匹配成功的路口，避免整体跳变 |
| 若改接高德/百度，坐标为 GCJ-02 | 需先转 WGS84（`src/util/geo.ts`），否则与 OSM/端侧体系不一致 |

### 9.2 鸿蒙端联调（**本项目最易踩坑处**）

1. `AppConstants.BASE_URL` 改为服务地址；`DATA_SOURCE_MODE` 设为 `AUTO`。
2. **明文 HTTP 放行** —— ⚠️ **当前 SDK 不支持该配置，工程里不要加**（2026-10-30 实测）

   曾在 `entry/src/main/module.json5` 的 `module` 节点下加 `networkSecurityConfig`，构建直接失败：

   ```
   hvigor ERROR: 00303038 Configuration Error
   Schema validate failed ... keyword: 'propertyNames',
   params: { propertyName: 'networkSecurityConfig' }
   ```

   核查依据：本机 SDK 的 schema 文件
   `D:\Apps\DevEco Studio\sdk\default\hms\toolchains\modulecheck\module.json`
   中 `module` 节点允许字段列表**不含** `networkSecurityConfig`（openharmony 那份同样不含），
   整个 SDK 目录检索该关键词零命中 → **该版本无此配置项，也就不存在"默认禁明文"这道关卡**。

   **结论**：先不配置，直接用 `http://` 请求实测。
   若联调时出现请求失败（如错误码 `2300007`），排查顺序改为：
   ① `ohos.permission.INTERNET` 已声明（工程已有）→
   ② 地址是否正确（模拟器 `10.0.2.2` 待实测，不通就换宿主机局域网 IP）→
   ③ Windows 防火墙是否放行 8080 →
   ④ 后端是否在运行。

3. **端侧三态开关**（必做，保障答辩演示）：

| 模式 | 行为 |
| --- | --- |
| `MOCK` | 恒用本地仿真（当前默认行为） |
| `AUTO` | 启动时请求 `/health`；成功走远程，失败/超时回落 Mock 并顶部提示"离线数据" |
| `REMOTE` | 硬连远程，失败即报错（仅联调排查用） |

> **答辩当天用 `AUTO`**：服务起没起来都能演示。

### 9.3 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 请求失败 `2300007` | 明文 HTTP 被拦截 | 配 `networkSecurityConfig` |
| 模拟器连不上 `10.0.2.2` | 该地址是沿用约定，**需实测确认** | ① 先在本机浏览器访问 `http://<宿主机IP>:8080/api/v1/health` 确认服务正常 ② 关闭/放行防火墙 8080 ③ 改为宿主机局域网 IP |
| 真机访问 `localhost` 失败 | 手机端 localhost 是手机自己 | 改局域网 IP |
| 返回 JSON 解析异常 | ArkTS 无 `any`，需逐字段构造实体 | 在 `RemoteTrafficRepository` 内做兜底解析，字段缺失给默认值 |
| 跨域疑虑 | 鸿蒙 App 非浏览器 | 无需配置 CORS |

## 11. 风险与对策

| 风险 | 对策 |
| --- | --- |
| **前后端算法口径不一致**（周期对不上） | 算法单测共享同一组用例；`/health` 返回算法版本号便于比对 |
| **联调环境不通**（最大风险） | 三态开关 + `AUTO` 降级；先在本机浏览器验证服务，再排查防火墙与 `networkSecurityConfig` |

| Node 后端在毕设评审中被认为"不够主流" | 文档中写明选型理由（算法零迁移、工期、演示稳定性）；表结构/ER/接口/分层章节完整，不缺失 |
| 地图 API 拿不到流量数据 | 已在 §2 明确其只能做路网与底图；配时输入固定为仿真并标注 `dataSource` |
| 评价指标仍是构造值 | P1 迁移时同步改为排队推演（见 §7.4 警示） |

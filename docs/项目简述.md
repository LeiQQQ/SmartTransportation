# 项目简述

**智行西安 · 基于 HarmonyOS 交通可视化系统**

以西安城墙内片区（17 个路口 / 27 条路段）为研究区域，构建「感知 → 优化 → 评价 → 服务」的信号配时闭环：
按实时流量用 Webster 模型重算周期与绿信比，并将算法结论翻译成用户能理解的信息（如「该方向还需等待 26 秒」）。

---

## 技术栈

### 客户端（用户端）

| 层次 | 选型 |
| --- | --- |
| 应用模型 | HarmonyOS **Stage 模型**（UIAbility + WindowStage） |
| 语言 / UI | **ArkTS** + **ArkUI 声明式**（`@Component` / `@State` / `@Prop` / `@Watch`） |
| 路由 | `Navigation` + `NavPathStack` + `NavDestination` |
| 图形 | `Canvas`（RenderingContext2D）自绘路网、车流、相位条、仪表盘 |
| 状态管理 | **V2**（`@ComponentV2` / `@Local` / `@Param` / `@Monitor`） |
| 手势 | `PinchGesture` / `PanGesture` 缩放平移 |
| 存储 | `@kit.ArkData` preferences（收藏） |
| 数据访问 | `Repository` 抽象 + Mock / Remote 双数据源，默认离线可用 |
| 构建 | Hvigor（`targetSdkVersion 26.0.0` / API 20+） |

### 服务端

- **Node.js 20 + TypeScript + Fastify 5**（`tsx` 运行与热重载）
- 分层：`routes`（接口）→ `service`（业务）→ `source`（数据源）+ `algo`（算法）
- 统一前缀 `/api/v1`，统一响应 `{ code, message, data, timestamp }`
- 接口模块：`area`（路口/路段）、`traffic`（片区指数/流量）、`signal`（方案/触发优化/优化评价）、`event`（列表/上报）、`health`
- 核心算法：Webster 最优周期 `C₀ = (1.5L + 5) / (1 − Y)`、按流量比分配绿信比、Webster 延误模型、饱和度 v/c 五级色阶

---

## 功能

### 用户端（HarmonyOS App）

底部四 Tab（首页 / 片区路况 / 事件中心 / 我的）+ 若干二级页：

- **首页态势总览**：片区拥堵指数仪表盘、路网色块、拥堵 TOP3
- **片区路况**：Canvas 拓扑路网，双指缩放平移，5s 刷新，饱和度五级色阶（畅通→严重）
- **路口实时**：相位放行车流动画、红绿灯倒计时、预计等待时间、进口道拥堵诊断
- **配时看板**：周期/损失时间/相位分配甘特图、优化前后四项指标对比、时段切换
- **事件中心**：事故 / 施工 / 管制 / 拥堵四类事件，列表筛选与上报
- **我的**：收藏路口（preferences 持久化）、数据说明、深色模式


## 说明

本项目未接入真实交通数据与信号控制系统，流量由高斯双峰模型（早 8 点、晚 18 点）+ 确定性伪随机扰动生成，
路网坐标依据公开地图资料手工建模，属仿真演示，不用于真实出行决策。

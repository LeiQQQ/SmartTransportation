# 项目简述

**基于HarmonyOS车流自适应信号灯系统设计与开发**

以西安城墙内片区（**20 个信号路口 / 32 条路段**，四门：安远 / 长乐 / 永宁 / 安定）为研究区域，构建「感知 → 优化 → 评价 → 服务」的信号配时闭环：
按实时流量用 Webster 模型重算周期与绿信比，并将算法结论翻译成用户能理解的信息（如「该方向还需等待 26 秒」）。

---

## 技术栈

### 客户端（用户端）

| 层次 | 选型 |
| --- | --- |
| 应用模型 | HarmonyOS **Stage 模型**（UIAbility + WindowStage） |
| 语言 / UI | **ArkTS** + **ArkUI 声明式**（`@ComponentV2` / `@Local` / `@Param` / `@Monitor`，V1 装饰器已清零） |
| 路由 | `Navigation` + `NavPathStack` + `NavDestination` |
| 图形 | `Canvas`（RenderingContext2D）自绘路网、车流、相位条、仪表盘；渲染按**底图 / 道路 / 标注**三层拆分（`common/render/`） |
| 状态管理 | **V2**（`@ComponentV2` / `@Local` / `@Param` / `@Monitor`） |
| 手势 | `PinchGesture` / `PanGesture` 缩放平移 |
| 存储 | `@kit.ArkData` preferences（收藏、离线事件） |
| 数据访问 | `Repository` 抽象 + **三态数据源**（`MOCK` / `AUTO` / `REMOTE`），默认离线可用，失败自动回落 |
| 构建 | Hvigor（`targetSdkVersion 26.0.0` / API 20+） |

### 服务端

- **Node.js 20 + TypeScript 5 + Fastify 5**（`tsx` 运行，✅ 已实现，默认端口 8080）
- 分层：`routes`（接口）→ `service`（业务）→ `source`（数据源）+ `algo`（算法）
- 统一前缀 `/api/v1`，统一响应 `{ code, message, data, timestamp }`
- **12 个接口**——`health`、`area`（路口/路段）、`traffic`（片区指数/流量）、`signal`（方案/触发优化/优化评价）、`event`（列表/上报）、`road`（百度实测路况快照）
- 核心算法：Webster 最优周期 `C₀ = (1.5L + 5) / (1 − Y)`、按流量比分配绿信比、Webster 延误模型、饱和度 v/c 五级色阶（算法自端侧平移，口径逐字一致）
- **数据源 `HybridDataSource`**：百度实时路况优先、缺失回落确定性仿真。百度 `congestion_sections` 的车速 / 拥堵距离 / 方向 / 趋势经 BPR 反解为**进口道饱和度与排队**，因此 `/traffic/flow`、`/signal/plan` 会随真实路况变化；每条进口道带 `source`（`BAIDU` / `SIM`）与 `note` 明细
- **实时通道：HTTP 短轮询**（端侧统一 30 s，由 `RefreshController` 控制），**未使用 WebSocket**；后端无 `ws` / `socket.io` 依赖
- 存储：**事件表已落 SQLite**（`server/data/store.db`，`node:sqlite` 内置模块，零第三方依赖）——重启不丢、多设备读同一份数据；历史流量快照未做
- 后台任务：`task/realtimeTask.ts` 每 45 s 拉一次百度路况写入内存快照（百度侧 60 s 缓存），业务接口同步读取，响应不受外部 RT 影响

## 功能

### 用户端（HarmonyOS App）

底部四 Tab（首页 / 片区路况 / 事件中心 / 我的）+ 若干二级页：

- **首页态势总览**：片区拥堵指数仪表盘、路网色块、拥堵 TOP3；均速优先取实测（按路段长度加权）
- **片区路况**：Canvas **仿真实地图**（城墙与垛口、环城公园绿地、道路按真实走向绘制），双指缩放平移，30 s 刷新；
  拥堵画在**道路**上——畅通 / 缓行 / 拥堵三档，档位越高色带越宽，并考虑**邻路传播**（一条路堵了，相邻路段跟着变色）；
  拥堵路名与路口名**标红加粗并优先占位**，标题栏标明「百度实时路况 / 仿真数据」
- **路口实时**：相位放行车流动画、红绿灯倒计时、预计等待时间、进口道拥堵诊断，并注明该进口道数字是实测反推还是本地仿真
- **配时看板**：周期/损失时间/相位分配甘特图、优化前后四项指标对比、时段切换
- **事件中心**：事故 / 施工 / 管制 / 拥堵四类事件，列表筛选与上报
- **我的**：收藏路口（preferences 持久化）、数据说明、深色模式


## 说明

信号配时算法与路网模型为本地实现（未接入真实信号机）；**路况等级来自百度地图开放平台实测**，
经反推后作为进口道饱和度的输入，未覆盖的进口道回落仿真。路网坐标依据公开地图资料手工建模，
属演示原型，不用于真实出行决策。

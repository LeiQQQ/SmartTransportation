## 1. 项目概述

### 1.1 研究背景

城市机动车保有量持续增长，拥堵、停车难、公交信息不对称成为通勤痛点。现有导航与公交类 App 普遍存在三个问题：

| 问题 | 表现 |
| --- | --- |
| 信息割裂 | 路况、公交、停车、限行分散在不同应用，用户需反复切换 |
| 终端割裂 | 手机、车机、手表各自为战，跨端接续体验差 |
| 弱网不可用 | 完全依赖云端，地下车库、隧道等弱网场景直接失效 |

HarmonyOS 的**分布式软总线**、**原子化服务**、**一次开发多端部署**能力，为上述痛点提供了新的解决思路。

### 1.2 项目目标

基于 HarmonyOS（ArkTS + ArkUI）设计并实现一款**一体化智慧交通出行助手**，实现：

1. **路况可视**：城市路网拥堵指数实时可视化，支持事件（事故 / 施工 / 管制）上报与查看。
2. **公交可查**：线路 / 站点双向查询、车辆实时到站（ETA）、常用线路收藏。
3. **出行可规**：驾车 / 公交 / 步行 / 骑行多方式路径规划，支持"最快 / 最短 / 避堵"策略。
4. **停车可寻**：附近停车场检索、空余车位展示、停车记录与计时提醒。
5. **跨端可续**：一次行程的查询状态在手机与车机 / 平板间无缝接续（分布式能力）。
6. **弱网可用**：本地缓存 + 离线兜底，无网络时仍可查看最近数据与收藏。

### 1.3 项目特色与创新点

| 创新点 | 说明 |
| --- | --- |
| ① 端云协同的可降级架构 | Repository 抽象层 + 双实现（Remote / Mock），服务端不可用时自动切换本地数据，毕设演示零风险 |
| ② 跨设备出行接续 | 基于分布式 KVStore 同步"当前行程意图"，手机查路线 → 上车后车机自动接续导航 |
| ③ 轻量化路况可视化 | 不依赖第三方地图 SDK，使用 ArkUI `Canvas` 自绘路况热力与线路，降低环境依赖 |
| ④ 声明式状态管理 V2 | 采用 `@ObservedV2 / @Trace / @Local` 新一代状态管理，精准刷新、性能优于 V1 |
| ⑤ 端侧出行画像 | 本地统计出行偏好（常用时段 / 方式 / 线路），首页智能推荐，保护隐私不上云 |

| 类别 | 指标 |
| --- | --- |
| 性能 | 冷启动 ≤ 2s；页面切换响应 ≤ 300ms；列表滚动稳定 60fps |

| 可维护 | 分层架构，UI 与数据解耦，Repository 可替换实现 |

## 3. 技术栈

### 3.1 总体选型

| 层次 | 技术选型 | 说明 |
| --- | --- | --- |
| 开发语言 | **ArkTS**（TypeScript 超集，静态类型） | HarmonyOS 官方首选应用语言 |
| UI 框架 | **ArkUI 声明式范式** | `@Component` + 链式属性布局 |
| 应用模型 | **Stage 模型**（`UIAbility` / `WindowStage`） | API 9+ 推荐模型，进程内多 Ability 共享 |
| 状态管理 | V1：`@State / @Prop / @Link / @Provide / @Observed / @ObjectLink`<br>V2：`@ComponentV2 / @Local / @Param / @ObservedV2 / @Trace` | 主用 V2（精准刷新），列表项用 V1 兼容 |
| 页面路由 | **Navigation + NavPathStack + NavDestination**（系统路由表 `route_map.json`） | 官方推荐，替代已废弃的 `@ohos.router` |
| 网络 | `@kit.NetworkKit` 的 `http` / `rcp`；`connection` 监听网络状态 | 统一封装 `HttpUtil` |
| 本地存储 | `@kit.ArkData`：`preferences`（轻量 KV）、`relationalStore`（SQLite 关系库） | 收藏、历史、离线缓存 |
| 分布式 | 分布式 KVStore（`@kit.ArkData`）+ `@kit.DistributedServiceKit` | 跨设备行程接续 |
| 定位 | `@kit.LocationKit` 的 `geoLocationManager` | 当前位置、持续定位 |
| 地图 | 方案 A：华为 **Map Kit**（`@kit.MapKit`）<br>方案 B（默认）：`Canvas` 自绘轻量路况图 | 见 [3.3](#33-地图方案选型) |
| 图形图表 | `Canvas` / `Shape` / `Path` 自绘 + `@ohos/mpchart`（可选三方） | 拥堵指数仪表盘、趋势折线 |
| 并发 | `TaskPool`（`@kit.ArkTS`）、`Worker` | 路径规划算法、数据解析放子线程 |
| 通知 | `@kit.NotificationKit` | 到站 / 预警 / 停车提醒 |
| 后台 | `@kit.BackgroundTasksKit` | 后台位置与定时任务 |
| 日志 | `@kit.PerformanceAnalysisKit` 的 `hilog` | 分级日志 |
| 测试 | 单元测试：`hypium` + `hamock`；UI 测试：UiTest | 工程已内置测试目录 |
| 服务端 | **Spring Boot 3 + MyBatis-Plus + MySQL 8 + Redis（推荐）** | 详见 [`docs/后端技术方案.md`](./后端技术方案.md)；缺失时由 `MockRepository` 兜底 |
| 版本管理 | Git + DevEco Studio | — |

### 3.2 开发环境

| 项目 | 要求 |
| --- | --- |
| IDE | DevEco Studio 6.x（与 `modelVersion: 26.0.0` 匹配） |
| SDK | HarmonyOS SDK（API 20+），`runtimeOS: HarmonyOS` |
| 构建 | Hvigor（`hvigorfile.ts`），支持 debug / release 双 buildMode |
| 运行设备 | HarmonyOS 6.x 真机（推荐）或本地模拟器 |
| 签名 | DevEco 自动签名（调试）；正式发布需 AGC 证书 |

### 3.3 地图方案选型

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| A. 华为 Map Kit | 专业底图、覆盖物、POI 搜索齐全 | 需 AGC 账号、开通服务、配置 `client_id` 与签名指纹 | 作为**增强项**，环境允许时启用 |
| B. Canvas 自绘 | 零外部依赖、完全可控、毕设演示稳定 | 无真实底图，需自建坐标变换 | 作为**默认实现**，保证项目可独立运行 |

策略：`IMapService` 接口抽象，两种实现通过配置开关切换（`AppConfig.USE_MAP_KIT`）。

## 4. 系统架构设计

### 4.1 总体架构

```
┌─────────────────────────────────────────────────────────────┐
│                        用户设备层                             │
│   Phone（主）        Tablet / 车机（扩展）      Wearable（扩展）  │
└────────────────────────────┬────────────────────────────────┘
                             │  分布式软总线 / KVStore 同步
┌────────────────────────────▼────────────────────────────────┐
│                     HarmonyOS 应用层（entry）                 │
│ ┌─────────────────────────────────────────────────────────┐ │
│ │  表现层 Presentation                                      │ │
│ │  pages/（首页·路况·公交·规划·停车·我的）  components/（复用组件）│ │
│ └───────────────────────────┬─────────────────────────────┘ │
│ ┌───────────────────────────▼─────────────────────────────┐ │
│ │  状态层 ViewModel / Store（@ObservedV2 + @Trace）          │ │
│ │  页面状态 · 加载态 · 错误态 · 业务编排                        │ │
│ └───────────────────────────┬─────────────────────────────┘ │
│ ┌───────────────────────────▼─────────────────────────────┐ │
│ │  领域/数据层 Repository（抽象接口）                         │ │
│ │  RemoteRepository  │  LocalRepository(Mock/缓存)           │ │
│ └──────────┬───────────────────────────────┬──────────────┘ │
│ ┌──────────▼───────────┐  ┌────────────────▼──────────────┐ │
│ │ 网络层 Network        │  │ 存储层 Storage                  │ │
│ │ http/rcp + 拦截器     │  │ preferences / relationalStore  │ │
│ └──────────┬───────────┘  └────────────────┬──────────────┘ │
│ ┌──────────▼───────────────────────────────▼──────────────┐ │
│ │ 能力层 Kits：LocationKit / MapKit / NotificationKit / ... │ │
│ └─────────────────────────────────────────────────────────┘ │
└────────────────────────────┬────────────────────────────────┘
                             │ HTTPS / JSON
┌────────────────────────────▼────────────────────────────────┐
│              服务端（可选）Spring Boot + MySQL + Redis         │
│         接口层 → 业务层 → 数据访问层 → 数据库/第三方交通数据       │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 分层职责

| 层 | 职责 | 约束 |
| --- | --- | --- |
| 表现层 | 页面布局、组件组合、用户交互、动画 | **不得**直接发起网络请求或操作数据库 |
| 状态层 | 持有 UI 状态、调用 Repository、异常与加载态管理 | 单页面一个 ViewModel，跨页共享态放全局 Store |
| 数据层 | 数据获取与缓存策略（先缓存后网络 / 失败降级） | 对上层暴露 `Promise<T>` 与统一 `Result` |
| 网络/存储层 | 协议实现、序列化、加解密、连接池 | 与业务无关 |
| 能力层 | 系统 Kit 封装（定位、通知、地图） | 统一权限申请入口 |

### 4.3 单向数据流

```
User Action ──► ViewModel.method() ──► Repository.request()
                                            │
                        ┌───────────────────┴───────────────────┐
                        ▼                                       ▼
                 RemoteDataSource                        LocalDataSource
                        │                                       │
                        └──────────────────► Result ◄────────────┘
                                              │
                                              ▼
                                    更新 @Trace 状态（V2）
                                              │
                                              ▼
                                     ArkUI 自动精准刷新 UI
```

## 6. 功能模块设计

### 6.1 模块划分总览

| 模块 | 入口页面 | 核心能力 | 依赖 Kit |
| --- | --- | --- | --- |
| M1 首页 | `HomePage` | 拥堵指数、限行/天气、快捷宫格、智能推荐 | LocationKit、NetworkKit |
| M2 实时路况 | `TrafficPage` | 路况可视化、事件列表、事件上报 | LocationKit、Canvas、MediaLibraryKit |
| M3 公交查询 | `BusPage` / `BusLineDetailPage` | 线路站点搜索、到站 ETA、收藏 | NetworkKit、relationalStore |
| M4 路径规划 | `RoutePlanPage` / `RouteResultPage` | 多方式多策略规划、步骤指引 | LocationKit、TaskPool |
| M5 停车服务 | `ParkingPage` / `ParkingDetailPage` | 附近车场、空位、计时提醒 | LocationKit、NotificationKit |
| M6 个人中心 | `MinePage` 及子页 | 登录、收藏、历史、设置、反馈 | ArkData、Preferences |

### 6.2 M1 首页

- **刷新机制**：进入页面优先读取本地缓存（≤5 分钟）立即渲染，再发起网络请求静默更新。
- **拥堵指数**：0–10 分，映射 畅通(0–2,绿) / 基本畅通(2–4,黄绿) / 轻度拥堵(4–6,橙) / 中度拥堵(6–8,深橙) / 严重拥堵(8–10,红)。
- **智能推荐**：依据 `TripRecord` 统计时段偏好（如工作日 08:00 常查 3 路公交），首页置顶推荐卡片。
- **下拉刷新**：`Refresh` 组件 + ViewModel `refresh()`。

### 6.3 M2 实时路况

- **可视化**：`Canvas` 绘制简化路网（主干道折线），按路段 `level` 着色，支持双指缩放与拖拽平移（`gesture` + `PanGesture` / `PinchGesture`）。
- **事件列表**：`List` + `LazyForEach` 懒加载，按类型/时间筛选，点击定位到路网。
- **事件上报**：选择类型 → 自动定位填充坐标 → 可选拍照（`CameraKit` / `@ohos.file.picker`）→ 提交（本地入库 + 队列重试上传）。

### 6.4 M3 公交查询

- **搜索**：`Search` 组件 + 防抖 300ms，同时匹配线路名与站点名，结果分组展示。
- **线路详情**：上下行切换（`Tabs`），站点列表标注"当前站/最近到站车辆"，`Scroll` 联动。
- **到站 ETA**：轮询（30s）或模拟推送更新，计算 `剩余站数`、`预计分钟 = 站数 × 平均站间时长`。
- **到站提醒**：选择目标站 → 后台计算 → `notificationManager` 发送通知。

### 6.5 M4 路径规划

- **输入**：起点默认"我的位置"（定位授权后），终点支持搜索历史、常用地址、地图选点。
- **策略**：`FASTEST` / `SHORTEST` / `AVOID_CONGESTION` / `AVOID_CHARGE`。
- **算法**：A\* / Dijkstra 在 `TaskPool` 子线程执行，避免阻塞 UI（毕设可使用内置图数据 + 权重表）。
- **结果**：多方案卡片横向滑动对比（时长、距离、红灯数、拥堵段数），点击展开分步指引。

### 6.6 M5 停车服务

- **列表**：按距离排序，展示 `空位/总位`、价格、类型（地面/地下/立体）、距离。
- **详情**：地址、营业时间、收费规则、联系电话、一键规划路线。
- **计时**：进入停车后开始计时（Preferences 记录起止），超时前 10 分钟发送通知提醒。

### 6.7 M6 个人中心

- **登录**：本地账号（手机号 + 密码 MD5 + 盐），用户表存 `relationalStore`；可选扩展华为账号（Account Kit）。
- **收藏/历史**：统一 `Favorite` 表（type + targetId），历史记录 `TripRecord` 表。
- **设置**：深色模式、消息开关、缓存清理、定位精度、关于与隐私政策。

### 9.2 统一网络封装

```ts
// common/utils/HttpUtil.ets
import { http } from '@kit.NetworkKit';
import { BusinessError } from '@kit.BasicServicesKit';

export class HttpUtil {
  private static client: http.HttpRequest = http.createHttp();

  static async request<T>(url: string, method: http.RequestMethod = http.RequestMethod.GET,
    params?: Record<string, string | number | boolean>): Promise<T> {
    const fullUrl = params ? `${url}?${HttpUtil.toQuery(params)}` : url;
    try {
      const resp = await HttpUtil.client.request(fullUrl, {
        method,
        header: { 'Content-Type': 'application/json', 'Authorization': PreferencesUtil.getToken() },
        connectTimeout: 10000,
        readTimeout: 10000
      });
      if (resp.responseCode === 200) {
        const body = JSON.parse(resp.result as string) as BaseResponse<T>;
        if (body.code === 0) {
          return body.data;
        }
        throw new Error(body.message ?? '业务异常');
      }
      throw new Error(`HTTP ${resp.responseCode}`);
    } catch (e) {
      const err = e as BusinessError;
      hilog.error(0x0000, 'HttpUtil', 'request failed: %{public}s', err.message);
      throw err;
    } finally {
      // 单次请求结束不销毁连接池时可省略 destroy
    }
  }
}
```

### 9.7 拥堵指数仪表盘（Canvas 自绘）

```ts
// components/TrafficGauge.ets
@Component
struct TrafficGauge {
  @Prop index: number = 0;      // 0~10
  private settings: RenderingContextSettings = new RenderingContextSettings(true);
  private ctx: CanvasRenderingContext2D = new CanvasRenderingContext2D(this.settings);

  build() {
    Canvas(this.ctx)
      .width(200).height(200)
      .onReady(() => {
        const cx = 100, cy = 100, r = 80;
        const start = Math.PI * 0.75, sweep = Math.PI * 1.5;
        // 底环
        this.ctx.lineWidth = 12;
        this.ctx.strokeStyle = '#E8EEF7';
        this.ctx.beginPath();
        this.ctx.arc(cx, cy, r, start, start + sweep);
        this.ctx.stroke();
        // 进度环（颜色按指数分级）
        this.ctx.strokeStyle = ColorUtil.levelColor(this.index);
        this.ctx.beginPath();
        this.ctx.arc(cx, cy, r, start, start + sweep * (this.index / 10));
        this.ctx.stroke();
        // 中心文字
        this.ctx.fillStyle = '#1A1A1A';
        this.ctx.font = '28vp sans-serif';
        this.ctx.textAlign = 'center';
        this.ctx.fillText(this.index.toFixed(1), cx, cy + 6);
      })
  }
}
```

| `ohos.permission.DISTRIBUTED_DATASYNC` | 跨设备同步 | 开启跨端接续时申请 |

安全措施：

1. 拒绝定位权限时自动降级为"手动选择城市 + 手动输入起终点"，不阻断主流程；
2. 密码本地加盐哈希存储，不明文、不上云；
3. 接口统一 HTTPS，Token 存 `preferences` 加密分区；
4. 隐私政策弹窗首次启动展示，用户同意后才采集位置；
5. 敏感日志脱敏，release 构建关闭 debug 日志。

## 14. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| Map Kit 需 AGC 资质与签名，可能无法开通 | 地图功能无法演示 | 默认采用 Canvas 自绘方案，Map Kit 作为可选增强 |
| 无真实交通数据源 | 数据为空 | 内置 Mock 数据集（线路/车场/路段），结构与真实接口一致，可平滑替换 |
| ArkTS 强类型与严格模式导致编译报错 | 进度受阻 | 遵循 `code-linter.json5` 规范，避免 `any`，接口显式类型 |
| 真机签名/证书问题 | 无法安装 | 使用 DevEco 自动签名调试，提前验证 |
| API 版本差异（V1/V2 状态管理混用） | 行为异常 | 统一约定：新页面用 V2，三方/系统组件兼容处用 V1 |
| 时间不足 | 功能未完成 | 按 P0/P1/P2 优先级裁剪，P2（分布式、通知）后置 |
